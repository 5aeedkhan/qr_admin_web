# Backend Integration Guide: Database Schema & Sync for QR System

Below is the **exact schema and data flow** your backend developer should implement to replicate the current Firebase system and keep it in sync with the .com software.

| Field | Type | Description | Sync Notes |

**Important:** The `qrCode` is deterministic and must be generated exactly as below.

## 2. QR Code Generation Algorithm (Deterministic)

The QR code is **not random**. It must be generated by the backend and .com software using the same logic:

```pseudo
function buildUserQrPayload(userId, userName, email, lastDate, createdAt):
  normalized = {
    "userId": trim(lowercase(userId)),
    "userName": trim(lowercase(userName)),
    "email": trim(lowercase(email)),
    "lastDate": lastDate.toIso8601String(),
    "createdAt": createdAt.toIso8601String()
  }
  material = jsonEncode(normalized)
  digest = sha256(utf8.encode(material))
  return "QR1:" + digest
```

- **If any of these fields change, the QR code changes.**
- `lastDate` is the most common trigger (e.g., subscription renewal).
- The mobile app verifies by scanning and matching this string against `users.qrCode`.

## 4. Sync Strategy with .com Software

### A) Users (Master in .com)
- .com software creates/updates users.
- Backend should expose:
  - `POST /users` (create)
  - `PUT /users/:id` (update)
  - `GET /users/:id` (fetch)
- On create/update, backend:
  - Calculates `remainingDays` from `lastDate`.
  - Generates deterministic `qrCode` via the algorithm above.
  - Generates `barcode` (random UUID prefix).

### B) Authentication (Firebase)
- When creating a new user in .com, backend should:
  - Create Firebase Auth user with email/password.
  - Store returned `authUid` in the user record.
  - **Do not log out the admin session** (use secondary Firebase app or admin SDK).

### C) Scan History (Mobile → Backend)
- Mobile app writes scan logs to `scan_history`.
- Backend can optionally:
  - Expose `GET /scans?uid=:uid` for analytics.
  - Forward to .com if needed.

## 5. API Endpoints Summary

| Method | Path | Purpose |
|--------|------|---------|
| POST | `/users` | Create user (from .com) |
| PUT | `/users/:id` | Update user (from .com) |
| GET | `/users/:id` | Get user (for mobile verification) |
| GET | `/users/qr/:qrCode` | Lookup by QR code (mobile scan) |
| POST | `/scans` | Log a scan (mobile) |
| GET | `/scans?uid=:uid` | Get scan history (mobile) |

## 6. Important Notes for Backend Dev

- **QR Code is deterministic** and must match the exact SHA-256 logic above.
- **authUid** is required for mobile login; create Firebase Auth user on user creation.
- **remainingDays** is calculated from `lastDate` vs today.
- **Status** should be `"active"` if `remainingDays > 0`, else `"inactive"`.
- **Barcode** is just a random unique string; used for alternate lookups.

---

## 7. Example Flow

1) .com software creates a user:
   - Sends `userName`, `userId`, `email`, `lastPayment`, `lastDate`.
   - Backend creates Firebase Auth user → gets `authUid`.
   - Backend generates `qrCode` via SHA-256 algorithm.
   - Backend generates random `barcode`.
   - Backend stores full user document.

2) Mobile app scans a QR:
   - Sends scanned string to `GET /users/qr/:qrCode`.
   - Backend returns user record if found.
   - Mobile app logs scan via `POST /scans`.

3) Admin updates user in .com:
   - Backend updates fields.
   - If `lastDate` changed, **regenerate qrCode**.
   - Mobile app sees new QR on next scan.

## 8. Code Snippets (Optional)

### JavaScript/Node.js QR Generation
```js
const crypto = require('crypto');

function buildUserQrPayload({ userId, userName, email, lastDate, createdAt }) {
  const normalized = {
    userId: userId.trim().toLowerCase(),
    userName: userName.trim().toLowerCase(),
    email: email.trim().toLowerCase(),
    lastDate: lastDate.toISOString(),
    createdAt: createdAt.toISOString(),
  };
  const material = JSON.stringify(normalized);
  const digest = crypto.createHash('sha256').update(material).digest('hex');
  return `QR1:${digest}`;
}
```

### C# QR Generation
```csharp
using System;
using System.Text;
using System.Security.Cryptography;
using Newtonsoft.Json;

public static string BuildUserQrPayload(string userId, string userName, string email, DateTime lastDate, DateTime createdAt)
{
    var normalized = new
    {
        userId = userId.Trim().ToLowerInvariant(),
        userName = userName.Trim().ToLowerInvariant(),
        email = email.Trim().ToLowerInvariant(),
        lastDate = lastDate.ToUniversalTime().ToString("yyyy-MM-ddTHH:mm:ss.fffZ"),
        createdAt = createdAt.ToUniversalTime().ToString("yyyy-MM-ddTHH:mm:ss.fffZ")
    };
    var material = JsonConvert.SerializeObject(normalized);
    using var sha = SHA256.Create();
    var hash = sha.ComputeHash(Encoding.UTF8.GetBytes(material));
    return $"QR1:{Convert.ToHexString(hash).ToLowerInvariant()}";
}
```
